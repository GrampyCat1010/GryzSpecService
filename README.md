# ГРУЗСПЕЦСЕРВИС

Полноэкранный сайт сервиса грузовой техники: личные и корпоративные заявки, каталог услуг, три темы, расчёт выезда, карты, реальные отзывы Яндекса и консультант с котом. HTML/CSS/JavaScript без сборщика; FastAPI; Supabase в production, SQLite для локальной проверки.

## Быстрый запуск

Требуется Python 3.12+. Из корневой папки проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# .env уже подготовлен. При новом клонировании: Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Откройте http://localhost:8000. В режиме `APP_ENV=development` сайт работает без ключей: заявки сохраняются в `data/local.db`. Подтверждение прямо сообщает, что это локальное сохранение. Карта, отзывы и контакты показывают понятные состояния до настройки; консультант без ключа объясняет разделы сайта. Подключённые каналы уведомлений работают и локально, поэтому для проверки без отправок оставьте ключи пустыми.

## Что заполнить в .env

| Значения | Назначение |
|---|---|
| `COMPANY_PHONE`, `COMPANY_ADDRESS`, `COMPANY_EMAIL` | Реальные публичные контакты; незаполненный телефон отображается заглушкой |
| `COMPANY_LATITUDE`, `COMPANY_LONGITUDE` | Обе координаты СТО: центр расчёта расстояния и метка на карте |
| `TELEGRAM_URL`, `MAX_URL` | Публичные HTTPS-ссылки компании в Telegram и MAX соответственно. Пустая ссылка скрывает иконку в футере; QR-коды в настройках формируются автоматически |
| `SUPABASE_URL`, `SUPABASE_KEY` | URL проекта и серверный `service_role` ключ; никогда не отдавать браузеру |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Бот и чат менеджеров для заявок |
| `TELEGRAM_WEBHOOK_SECRET`, `PUBLIC_URL` | Секрет webhook и публичный HTTPS-адрес сайта |
| `TELEGRAM_MANAGER_IDS` | Необязательный список Telegram user ID через запятую для кнопки «Оформлено» |
| `MAIL_TRANSPORT=resend`, `RESEND_API_KEY`, `SMTP_FROM`, `MANAGER_EMAIL` | Отправка email через HTTPS, подходящая для Render Free. Без домена используйте `onboarding@resend.dev` и email аккаунта Resend как получателя |
| `MAIL_TRANSPORT=smtp`, `SMTP_*` | Альтернативная отправка через SMTP с TLS на хостинге, где SMTP разрешён |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` | Ключ и актуальное имя модели консультанта |
| `YANDEX_MAPS_API_KEY` | JavaScript API Яндекс Карт для выбора точки; ограничьте ключ доменом сайта |
| `YANDEX_ROUTING_API_KEY` | Серверный ключ Matrix API для дорожного расстояния |
| `YANDEX_ORG_ID` | Числовой ID вашей организации на Яндекс Картах для официального виджета отзывов |
| `COMPANY_YEARS` | Необязательный подтверждённый стаж; пустое значение не показывается |

Ключи Matrix API и Maps JavaScript API могут требовать отдельных подключений/тарифов Яндекса. Права и квоты определяются вашим договором. `YANDEX_ORG_ID` — числовой ID в URL карточки организации, не ключ API. Отзывы показывает официальный iframe, сайт не собирает и не выдумывает оценки.

Для координат используйте точку в дробной части. Если центр пока неизвестен, оставьте обе переменные закомментированными или пустыми. Не используйте демонстрационные координаты из примера как фактический адрес компании.

## Создание базы Supabase

1. Создайте проект Supabase.
2. Откройте **SQL Editor → New query**, вставьте **весь** `migrations/001_supabase.sql`, выполните Run.
3. SQL создаст таблицы `orders`, `notification_logs`, функции транзакционного приёма/выдачи заданий/статистики и закрытый bucket `order-photos`.
4. Заполните серверные URL и `service_role` ключ в `.env` или в переменных Render. Публичный anon ключ не подходит: таблицы закрыты RLS и правами.

Статистика завершённых заявок считается из БД. Кнопка «Оформлено» в Telegram переводит заявку в `completed`; произвольные цифры на сайте не используются. Тестовые заявки локального запуска не попадают в Supabase.

## Render Free

В репозитории есть `Dockerfile` и `render.yaml`. Создайте Render Blueprint из своего репозитория либо Web Service с Docker. Настройте переменные окружения по `.env.example`, обязательно `APP_ENV=production` и `PUBLIC_URL=https://ваш-сервис.onrender.com`. Файл `.env` не коммитится и не попадает в Docker image.

У бесплатного Render эфемерная файловая система и сервис засыпает без трафика; первая загрузка может занять больше времени. Постоянная база находится в Supabase. Фотографии временно дублируются в закрытом Supabase Storage для повторной доставки после перезапуска. После доставки в Telegram и email приложение удаляет локальные и облачные временные копии. Это не бессрочное хранение фотографий.

Render Free блокирует исходящие SMTP-порты 25/465/587. Поэтому по умолчанию настроен HTTPS-транспорт Resend. Для тестов без собственного домена задайте `SMTP_FROM=onboarding@resend.dev`, а `MANAGER_EMAIL` установите равным адресу, с которым зарегистрирован аккаунт Resend. Такой режим предназначен для доставки на этот адрес; для произвольных получателей подтвердите собственный домен в Resend. SMTP-реализация также есть и переключается одной переменной на другом тарифе/хостинге. Соблюдайте квоты выбранного почтового сервиса.

В production приложение автоматически регистрирует Telegram webhook при каждом запуске. Укажите `PUBLIC_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `TELEGRAM_WEBHOOK_SECRET` в переменных Render. Для ручной регистрации или диагностики можно использовать скрипт:

```powershell
.\.venv\Scripts\python.exe scripts/register_webhook.py
```

Бот должен присутствовать в целевом чате и иметь права отправки/удаления сообщений. Webhook проверяет секрет, chat ID, а при заполненном списке — ID менеджера. Кнопка завершения удаляет все связанные сообщения, фото и геометку из Telegram. Для старых сообщений Telegram может запретить удаление; тогда кнопка заменяется отметкой о завершении. Запись в БД сохраняется.

Docker-команда доверяет forwarded headers внешнего прокси: предназначена для Render, где контейнер доступен через прокси платформы. При самостоятельном публичном размещении ограничьте `--forwarded-allow-ips` адресами своего прокси.

## Расчёт стоимости

Все тарифы находятся в `config/pricing.json`. Начальные значения — настраиваемые ориентиры, проверьте их перед публикацией. Сумма всегда заново считается сервером и записывается в JSON заявки.

- Работы: базовая цена услуги × коэффициент типа транспорта.
- Выезд: 10 000 ₽, включая первые 20 км от центра сервиса; далее 80 ₽/км в одну сторону. Значения меняются в конфигурации.
- Срочность: ×1,2 на предварительную сумму.
- При доступном Matrix API берётся дорожное расстояние. Иначе расстояние по прямой ×1,3 с явной пометкой «оценка».
- При неизвестном расстоянии оно не выдаётся за ноль: интерфейс сообщает, что путь ещё не учтён.
- Для запчастей и маршрута свыше 500 км сумма согласуется индивидуально. Географического запрета на заявки нет.
- Корпоративная заявка не использует калькулятор.

При смене тарифов обновите пояснение в интерфейсе, если изменяется сама формула. Приблизительная цена не заменяет согласование маршрута, диагностику и предложение менеджера.

## Как сохраняется и доставляется заявка

`POST /api/orders` и `/api/corporate-orders` принимают multipart: поле `payload` с JSON и до пяти `photos`. Заголовок `Idempotency-Key` обязателен, формат UUID. Формы генерируют его автоматически и повторно используют при сетевом сбое. Изменение данных создаёт новый ключ.

Валидация → единый canonical JSON → транзакция БД с двумя заданиями уведомлений → временное сохранение фото → разрешение доставки. Telegram и email читают один объект из БД. Почта получает полный текст, JSON и фотографии. Telegram получает текст, геометку, фотографии и кнопку «Оформлено».

Сбой канала не удаляет заявку и не останавливает второй канал. Фоновый worker забирает задания с блокировкой и повторяет с задержкой до часа. Успех браузеру означает сохранение заявки и постановку в очередь, а не мгновенную доставку. В production оба канала ожидаются даже при незаполненной конфигурации; после исправления переменных перезапустите сервис, worker продолжит доставку.

Фото проверяются по содержимому, перекодируются в JPEG с удалением метаданных, уменьшаются до 1920 px. Исходные имена не используются. Неуспешная загрузка фото возвращает ошибку; повторная отправка с тем же ключом продолжает тот же заказ. Такая заявка не доставляется частично. Статусы `upload_failed` требуют повторной отправки клиентом; нельзя восстановить не попавший в хранилище файл после закрытия клиентом формы.

Провайдеры не гарантируют строго однократную доставку при обрыве соединения в момент подтверждения. Resend использует Idempotency-Key; Telegram сохраняет прогресс отправленных частей, но редкий дубль на границе ответа возможен. Один worker рассчитан на один бесплатный экземпляр Render.

## Перед публикацией

Замените подготовленный текст `content/privacy.txt` реквизитами и условиями вашей организации. Это редакционный шаблон, а не готовый юридический документ. Уточните требования к размещению/локализации персональных данных для выбранных Supabase, Telegram, почты и ИИ-провайдера. Установите срок хранения заявок и порядок удаления. Без реальных контактов и реквизитов сайт остаётся локальной демонстрацией.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

21 тест проверяет сохранение единого JSON, повторную отправку, ошибки БД/фото, корпоративную заявку, серверные правила направления, сохранность фото при сбое email, удаление после доставки, завершение в Telegram, расчёт маршрута и контракт закрытого Supabase Storage. Внешние провайдеры в тестах заменены mock-ответами; реальные отправки не выполняются.

Для локального браузерного smoke-теста: установите Playwright для Node.js и Chrome, запустите сервер на 8000, выполните `node scripts/check_browser.cjs`. Скрипт создаёт локальную тестовую заявку, проверяет чат/темы/адаптивность и сохраняет скриншоты в `.impeccable/review/`. Не запускайте его на production с подключёнными каналами.

Исходные дизайн-материалы сохранены в `ImagesForCoding`. Кот оптимизирован в `static/images/cat.webp`; для повторного экспорта — `python scripts/prepare_assets.py`. Шрифты Unbounded и Golos Text хранятся локально с лицензиями OFL. Код и оформление сайта-источника не использовались.
